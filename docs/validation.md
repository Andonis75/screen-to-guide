# 知行册：验证记录与能力边界

记录日期：2026-10-25。当前项目版本：0.2.0；下列历史视频与播放器记录分别标明当时版本。

本页区分真实视频试用、工程测试和后续计划。统计来自本地运行记录，仅公开可复核的汇总结果；原始媒体、转写、含本机路径的处理记录及用户素材不随代码仓库发布。以下数字不是通用准确率或跨设备性能基准。

0.2.0 新增字幕优先、绑定来源的阶段恢复、可选链接获取和简洁概览。第 5 节单独记录这些路径的实测；以下 0.1.x 的全量转写耗时和测试数量保留为历史记录。

## 2. 真实教学视频

### MCP 原理与 Windows 实操

输入为技术爬爬虾发布的 [MCP 教学视频](https://www.bilibili.com/video/BV1AnQNYxEsy/)。完整素材通过外部 yt-dlp 获取后，交给项目本地教学入口处理。

| 指标 | 本次结果 |
| --- | --- |
| 源视频时长 | 909.736 秒，约 15 分 10 秒 |
| 源分辨率 | 1920 × 1080 |
| 本地 ASR | 全音轨已提交，返回 425 段带时间转写 |
| 基础选帧与 OCR | 96 张源画面，OpenVINO CPU OCR 完成 |
| 覆盖索引 | 31 个时间窗，每窗最多 30 秒 |
| 最终教材 | 13 章、17 张来源截图 |
| 材料准备耗时 | 206.144 秒 |
| 教学模式视觉大模型 | 未调用 |
| 生成方式 | Agent 整理中间 manifest，由固定渲染器生成 HTML、Markdown、JSON |

206.144 秒是 `prepare_lesson.py` 的材料准备用时，包含该入口的处理工作，**不包含视频下载、Agent 阅读与写作、外部资料核验和内容复审**，不能称为完整文档的总生成时间。

完整转写、联系表、必要补采片段和全部 13 章参加了一轮内容检查，记录未发现待修复的实质问题。检查特别区分原片演示与当前文档补充，以及“已安装连接”和“已执行任务”。这次检查没有在用户账号执行视频里的 MCP 配置命令，也不等于视频中每项工具都在本机安装测试过。

材料于 0.1.4 生成；0.1.5 修复通用播放器后，从同一中间稿重新渲染。Markdown 与正文 JSON 的哈希保持一致，最终文件没有另行手动补写。源 AV1 视频生成了 H.264/AAC 浏览器兼容副本，副本时长 909.734 秒，与源差 0.002 秒；阅读截图来自源文件，未拿播放副本二次截图替代。

### 另一条讲解与实操混合视频

| 指标 | 本次结果 |

| 时长 / 分辨率 | 342.471769 秒 / 640 × 360 |
| ASR / 基础画面 | 全音轨提交，171 段转写 / 64 张画面 |

两条教学视频说明流程已经处理过不同长度与清晰度的材料，不足以推导“所有教学视频都能准确转换”。

## 3. 软件操作录屏与工程样例

早期本地验证记录见 [`references/validation.md`](../references/validation.md)。其中包含：

- 本地 Qwen2.5-VL 经 OpenVINO GenAI 对虚构三阶段录屏完成两次真实三帧推理。该素材验证实际模型能够运行，不能用来代表真实业务准确率。
- 对一段约 166.75 秒的手机拍屏素材进行分析，发现同时送入前后画面会导致状态混淆，随后改为只描述绑定的当前画面，并复测相关片段。
- 对 HEVC/HDR 素材生成 H.264/AAC、SDR 回放副本，并检查时间轴与浏览器定位。源截图和源视频保持独立。

已观察到转写同音词错误、短暂变化漏帧及重复操作遗漏。因此，软件录屏模式保留关键片段回看与动作证据复审，不把模型逐帧初稿直接当作完整 SOP。

## 5. 0.2.0 字幕、恢复与概览验证

### 公开链接获取

使用新增的 `acquire_video.py`，匿名获取同一条 MCP 视频，未导入浏览器登录信息。首次下载和完整解码检查耗时 28.766 秒，得到 909.736 秒、1920×1080 的 AV1/AAC 媒体，大小 41,667,585 字节；恢复修复后显式 `--resume` 用时约 0.88 秒，命中经过哈希检查的完成缓存，没有重新下载。

本次平台没有向匿名请求提供可下载字幕，状态记录为 `unavailable`，后续路线为本地 ASR。因此这条实测证明了下载、实际清晰度检查、完整解码和缺字幕回退，不是平台字幕成功下载的案例。字幕成功写入、语言选择及失败恢复由受控测试覆盖。

### 同一视频的材料复用

为验证跳过重复转写，将该视频先前生成的 425 段带时间转写 JSON 作为 `--subtitle-file` 输入。它是已有 ASR 结果，**不是平台原生字幕**。新输出目录重新抽取 96 张原帧、执行 OCR 并制作回放副本，材料准备耗时 205.011 秒；没有再次执行语音模型推理。

同样参数显式续跑，首次为 0.757 秒；恢复修复完成后的再检为 0.742 秒。两次均先检查来源、缓存内容及产物哈希，再复用转写、帧、OCR 和回放四个阶段。这个时间仅代表材料缓存检查，**不包含 Agent 阅读、写作、内容核验或生成全新教材**。

### 文档渲染与页面

在同源、截图哈希一致的前提下，复用此前核对过的 13 章中间稿与 17 张来源图片，在中间稿中加入 5 条概览，由更新后的固定渲染器生成 HTML、Markdown 和 JSON。补采细节图的复用来源另行记录。没有手动修改生成后的正文文件；这次是渲染兼容性验证，不算第二次独立语义质量评测。

浏览器检查确认“先看重点”及目录入口显示正常，章节入口可以定位，已查看的章节图片加载为 1920×1080，页面没有横向溢出。公开的 9 秒合成样例也通过构建脚本重新生成，包含简洁概览与「知行册」名称；在支持 Range 请求的本地预览服务上，第一章实际停在 3 秒并显示章末提示。

### 恢复行为

新增回归覆盖来源/参数变化、损坏产物、OCR 或 ASR 中断、缺失播放附件，以及缓存登记中断后的重试。材料恢复会保留被替换的旧回放文件；出现来源不一致时清除可复用阶段，避免沿用错误来源。实际 Windows 目录 junction 验证在写入前被拒绝。

下载恢复另覆盖 yt-dlp 会跳过现有完整文件的真实行为：已损坏或来源记录不匹配的完整视频先隔离留存，再重新获取；有效的断点文件保留。字幕在独立暂存目录下载，完成时间校验后才放入视频旁，失败残留和被修改的旧字幕不会被自动采用。直接调用已安装 yt-dlp 的零网络回归还覆盖了“字幕移动到最终目录后，返回字段仍指向原临时路径”的实际行为。

## 6. 如何复现定向测试

0.1.5 发布前的历史全量 Python 测试为：72 项通过、1 项跳过，包含 165 个子用例通过；同次 Node 播放器测试 14 项通过。测试检查工程行为，不替代视频语义质量评估。

**0.2.0 发布前全量运行：119 项 Python 测试通过、1 项跳过，221 个子用例通过；Node 播放器测试 14 项全部通过，Skill 格式检查通过。** Windows 下设置 `PYTHONUTF8=1`，本次 Python 测试用时 8.95 秒；模型效果与平台下载质量不由这些单元测试数量衡量。

在项目根目录、完成运行环境准备后执行：

```powershell
$env:PYTHONUTF8="1"
.\.runtime\venv\Scripts\python.exe -m unittest discover -s tests -p test_lesson_render.py -v
.\.runtime\venv\Scripts\python.exe -m unittest discover -s tests -p test_prepare_lesson.py -v
.\.runtime\venv\Scripts\python.exe -m pytest tests -q
node --test tests/test_lesson_playback.cjs
```

Node.js 仅用于这组播放器工程测试，不是最终离线 HTML 的额外运行依赖。重新处理真实视频的方法见 [技术设计与运行说明](technical-design.md)，其中区分材料生成和 Agent 完成教材两个阶段。

测试输出数量可能随代码更新变化；提交新版本时应以当次运行结果为准，不把不同历史运行中的数量相加当成当前总测试数。

## 7. 下一步验证计划

以下项目尚未作为已完成能力对外承诺：

1. 在 Intel Core Ultra AI PC 上分别验证 CPU、GPU、NPU 对对应模型和任务的支持情况，记录硬件型号、模型版本、耗时、内存与功耗；通过后再发布设备对比数据。
2. 建立带人工标注的多视频评估集，覆盖短暂弹窗、快速操作、不同口音、低清画面和长课程，分别统计漏项、错词、错误步骤与来源匹配情况。
3. 完善超长视频分段处理，保留原片时间偏移与跨段章节关系；当前单段仍为 30 分钟、2 GiB 上限。
4. 改进素材获取体验与清晰度检查，但不承诺所有平台、所有权限状态都能下载完整最高画质。

当前可以据实描述为：**具有本地 OpenVINO 推理、Agent 内容整理、固定文档渲染和章节回看能力的可运行项目，已完成选定真实样例与工程测试验证。**
