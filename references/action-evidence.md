# 动作依据与交付前复审

## 先记录实际事件，再写指令

操作指南需要告诉读者做什么，但不能为了补齐步骤而新增录屏中没有的点击。先把关键片段整理成事件顺序：前置界面 → 可观察的主动操作 → 系统反馈 → 下一状态。对自动跳转、自动提交和异步加载单独记录为系统事件。

以下现象只能提供线索，不能单独证明点击：按钮上有光标、按钮曾经可用、按钮文字出现、弹窗消失、后面出现成功提示、旁白说“然后发送”。必须回看前后连续状态，确认中间是否确实需要另一个主动动作。

尤其检查多层弹窗：确认框的按钮可能已提交整个操作，关闭后底层表单可能直接进入加载。如果底层按钮在覆盖层尚未消失时就已进入处理中，应记录自动继续，并指导读者等待。不要再补一个点击底层按钮的步骤。只有确实看到回到可交互状态后另一次操作，才写第二次点击。

无法确定额外点击是否发生时，继续取更密的连续帧；有了明确提交及后续成功，可写“确认后等待完成”。不要用猜测要求读者重复提交。

## 固定采样工具

在 Skill 目录中运行：

```powershell
python .\scripts\sample_sequence.py "D:\录屏\操作.mp4" --start 120 --end 135 --output-dir "D:\手册\本次\analysis\提交片段"
```

默认最多约每秒 8 帧，使用源视频实际 PTS，输出 `sequence.json`、原始截图和联系表。开始/结束参数与教程播放时间使用同一归零时间轴。短暂弹窗或异步提交可加 `--fps 30`；每段最多 30 秒、600 张，超过上限分段检查。采样只是阅读材料，不自动判定点击。

把需要引用的帧拷入本次指南的 `frames/`，按 `sequence.json` 的真实时间与实际 PTS 加入 manifest 的 `frames`，不要用请求的采样时间代替真实帧时间。不同片段中的原始帧 ID 会重复；合并时统一加上各片段的唯一前缀，并同步引用。一个片段的全部帧不必都进入阅读正文。

## 内部动作记录

新教程必须设置 `tutorial.action_evidence_required: true`。顶层增加 `action_evidence` 数组，每条记录包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 此记录的唯一 ID |
| `event_id` | 同一次实际事件的关联 ID，可省略并默认同 `id`；同一次事件不能同时说成自动发生和人工点击 |
| `kind` | `click`、`input`、`select`、`navigate`、`automatic` 或 `wait` |
| `frame_ids` | 本次源视频的真实帧，点击与导航至少有两个不同时刻的前后帧 |
| `start_seconds` / `end_seconds` | 覆盖这些帧和该事件的实际时间范围 |
| `support` | `observed_transition`（观察到前后变化）、`visible_value`（可见字段值）、`system_transition`（系统自动过渡）或 `inferred`（仅推测） |
| `description` | 具体观察到的事件；说明触发动作、系统反馈以及自动/主动的判断依据 |

`click`/`navigate` 只接受 `observed_transition`；`input`/`select` 还可接受 `visible_value`，后者可用于指导填写可见配置，但不要宣称看到了逐字输入。`automatic` 使用 `system_transition`；`wait` 可引用系统过渡或已观察的变化。`inferred` 不用于最终教程。

每步的 `action_refs` 必须与 `actions` 等长，并逐条对应：

```json
{
  "actions": ["点击确认按钮。", "等待处理完成，进入结果页。"],
  "action_refs": [["confirm-click"], ["processing-result"]]
}
```

一条写给读者的动作可引用多条事件，但不要把数次操作挤进一句来逃过核验。教程中的“等待自动完成”引用 `automatic`/`wait` 记录；“点击”引用实际主动操作记录。结构校验不会读懂画面或证明描述为真，因此还要进行下面的独立复审。

## 独立复审

复审者只拿到本次视频、相关连续帧、动作记录和候选教程，不接收写稿者的预期答案或旧项目结论。复审者要实际查看源画面，不仅检查 JSON 字段齐全。

检查重点：

1. 每条主动动作是否有依据；是否把自动过渡、按钮加载、光标停留误写为额外点击。
2. 多层弹窗的最后一次确认是否已经提交；是否错误要求重复发送/保存/支付/删除等操作。
3. 数字、单选项、截止日期以最后实际生效的状态为准；中途演示的选项不混入最终步骤。
4. 输入框已有的 `%`、货币、单位等后缀与实际输入文本分开写；预填和异步加载的内容不写成必须手动重输。
5. 起点、准备项、所有关键按钮与异常分支是否足够跟做；结果只写录屏能支持的范围。
6. 阅读正文是否夹带制作备注、无关原文、笼统“需核对”；可见图片与视频起点是否有助于执行该步。

复审输出 `analysis/action-review.json`：列出范围、审阅材料、逐项发现、是否有未解决问题。每个发现写明步骤/动作编号、视频时间和理由。执行智能体依据源视频重建记录和候选 manifest，再请复审者复查受影响动作。复审通过才生成最终阅读版。

复审不是用户确认，也不是准确率测评。保留内部 `pending` 和 Agent 处理信息，正文展示已经完成整理的操作说明。
